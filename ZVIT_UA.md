# Розробка лендінгу інтернет-магазину TERRA

Індивідуальне завдання з дисципліни «Прикладні інформаційно-аналітичні рішення в маркетингу».

Виконав: Арабаджи Віталій.

## Мета роботи

Ознайомитися зі структурою лендінгу інтернет-магазину, навчитися редагувати HTML, CSS і JavaScript, підготувати сайт до публікації на GitHub Pages та налаштування вебаналітики.

## Вибір і редагування шаблону

Для роботи обрано Edgecut із сайту HTML Design. Вихідний шаблон присвячений меблям і містить головний екран, картки товарів, інформаційні розділи та контактну форму. HTML і CSS завантажено з офіційного демо. Збережено компонент картки товару та його стилі; назву, тематику, тексти, зображення, структуру змісту й оформлення перероблено.

Навчальний магазин TERRA представляє терасну та фасадну дошку, вікна, двері й фурнітуру. Цільова аудиторія — власники будинків, дизайнери та будівельні компанії, які порівнюють матеріали для проєкту. Основна цільова дія — вибір матеріалів і формування заявки.

## Структура лендінгу

Головний екран пояснює тематику магазину й містить перехід до каталогу. Каталог включає шість демонстраційних моделей, поділених на п’ять категорій. У картках зазначено назву, умовні характеристики, ціну та одиницю продажу. Інформаційний блок пояснює послідовність вибору матеріалів. Контактний розділ веде до кошика й форми заявки.

Файли розділено за призначенням: головна сторінка `index.html`, оформлення в `css`, зображення в `images`, інтерактивність у `js`. Така організація відповідає структурі, описаній у методичних вказівках. Використано відносні шляхи до локальних ресурсів.

## Інтерактивність і робота із заявкою

JavaScript фільтрує товари за категорією, сортує за умовною ціною та додає їх до кошика. Зміна кількості оновлює загальну суму. Кошик зберігається в localStorage, якщо браузер дозволяє використовувати це сховище. Передбачено обробку помилкових збережених даних і обмеження кількості.

Форма перевіряє заповнення імені й телефону. Після підтвердження браузер формує текстовий файл з обраними товарами, кількістю, умовною сумою та коментарем. Цей сценарій не створює реального замовлення і не надсилає дані продавцю. Такий результат прямо позначено на сторінці.

## Підготовка до публікації

Проєкт не потребує складання або серверного застосунку. Для публікації необхідно завантажити файли у власний репозиторій, вибрати гілку `main` і папку `/(root)` у GitHub Pages та перевірити отриману адресу. Покрокову інструкцію наведено в README_UA.md.

Стан на момент підготовки цього звіту: вихідні файли готові; публікацію в обліковому записі студента ще не виконано. Посилання на реальний опублікований сайт не наведено, оскільки його ще немає.

## Підготовка Google Analytics

У проєкті підготовлено модуль GA4. Після внесення власного Measurement ID та згоди користувача він завантажує Google tag і передає події перегляду сторінки, вибору категорії, додавання й вилучення товару, формування файлу заявки. Ідентифікаційні дані з форми не включаються в параметри цих подій.

Стан на момент підготовки цього звіту: Measurement ID не заданий, тому збір даних не ввімкнений. Для виконання відповідного пункту завдання потрібно підключити власний ресурс GA4, перевірити реальні події у Realtime або DebugView й додати скриншоти. Доказів збору даних у цьому звіті немає.

## Висновок

Підготовлено працездатний локальний лендінг на основі шаблону HTML Design та файли для публікації на GitHub Pages. Опрацьовано HTML-структуру, CSS-оформлення, локальні зображення та JavaScript-взаємодії. Завершення всього індивідуального завдання потребує фактичної публікації сайту й демонстрації статистики у власному Google Analytics студента.

Джерела: надані методичні вказівки ОНЕУ, Edgecut від HTML Design, офіційна документація GitHub Pages та Google Analytics. Точні посилання наведено в README_UA.md.
