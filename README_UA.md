# TERRA — індивідуальне завдання зі сторінки 5

Дисципліна: «Прикладні інформаційно-аналітичні рішення в маркетингу».
Тема: «Розробка лендінгу інтернет-магазину та його розміщення на сервері GitHub».
Виконала: Ольга Штирбулова. Номер групи та викладача потрібно вписати у звіт самостійно.

## Як відкрити

1. Розпакуйте архів повністю.
2. Відкрийте `index.html` подвійним клацанням у сучасному браузері.
3. Перевірте каталог, категорії, сортування, кошик і завантаження заявки.

Встановлювати Node.js або інші програми не потрібно. Зображення, стилі та скрипти зберігаються локально. Інтернет потрібний для переходу на зовнішні джерела, публікації та Google Analytics.

## Що зроблено

- Завантажено HTML та CSS з офіційного демо безкоштовного шаблону Edgecut від HTML Design.
- Перероблено тематику меблевого магазину на магазин терасної та фасадної дошки, вікон, дверей і фурнітури.
- Використано компонент картки товару Edgecut: `furniture_section`, `box`, `img-box`, `detail-box`, `price_box` та його CSS. Дизайн суттєво змінено окремим файлом стилів.
- Додано українські тексти, оригінальні SVG-ілюстрації, шість демонстраційних моделей, п’ять категорій та умовні ціни.
- Реалізовано фільтрацію, сортування, кошик зі зміною кількості й підрахунком суми.
- Реалізовано локальне збереження кошика; якщо браузер обмежує сховище, кошик працює в межах поточного відкриття сторінки.
- Додано форму, яка створює текстовий файл заявки. Вона не надсилає дані продавцю та не здійснює оплату.
- Підготовлено опціональний код GA4. Без справжнього Measurement ID аналітика вимкнена.

## Публікація на GitHub Pages

1. Увійдіть у свій GitHub та створіть публічний репозиторій, наприклад `olga-shtyrbulova-marketing`. Якщо викладач вимагає номер групи в назві, додайте його.
2. Через **Add file → Upload files** завантажте `index.html`, папки `css`, `js`, `images`, `reference`, обидва Markdown-файли та `.nojekyll`. Завантажуйте вміст розпакованого проєкту, а не ZIP і не зовнішню папку, яка приховає `index.html` на другому рівні.
3. Підтвердьте завантаження через **Commit changes**.
4. Відкрийте **Settings → Pages**.
5. У **Source** виберіть **Deploy from a branch**, далі гілку **main** та **/(root)**. Натисніть **Save**.
6. Дочекайтеся завершення публікації. Точну адресу візьміть зі сторінки Pages.
7. Відкрийте сайт за отриманою адресою та перевірте зображення, каталог і кошик.

Файл `index.html` має бути в корені обраної папки публікації. Для GitHub Pages використано відносні шляхи без початкового `/`, тому ресурси працюють і в репозиторії-проєкті.

## Підключення Google Analytics 4

1. У власному Google Analytics створіть ресурс GA4 і вебпотік із точною HTTPS-адресою опублікованого сайту.
2. Скопіюйте Measurement ID виду `G-…`. Це публічний ідентифікатор вимірювання, не пароль.
3. У `js/config.js` замініть порожній рядок `gaMeasurementId: ''` на свій ідентифікатор. Не додавайте секретні ключі або паролі.
4. Для перевірки тимчасово встановіть `gaDebug: true`, завантажте змінений файл у GitHub і дочекайтеся оновлення Pages.
5. Відкрийте сайт за HTTPS та дозвольте аналітику в діалоговому вікні. Перегляд через локальний `file://` не використовуйте для демонстрації GA4.
6. Відкрийте **Realtime** або **DebugView** у своєму GA4. Натисніть категорію, додайте товар до кошика, змініть кількість і завантажте тестову заявку.
7. Переконайтеся, що події видно в GA4. Блокувальник реклами або відхилена згода можуть перешкоджати збору. Збережіть власні скриншоти як докази для викладача.
8. Після перевірки поверніть `gaDebug: false`.

| Подія | Умова |
| --- | --- |
| `page_view` | Завантаження сторінки після дозволу на аналітику |
| `select_content` | Натискання категорії товарів |
| `add_to_cart` | Додавання одиниці товару |
| `remove_from_cart` | Зменшення кількості товару |
| `generate_lead` | Формування локального файлу заявки |

`generate_lead` у цьому навчальному проєкті означає формування файлу, а не отримання заявки продавцем. Подія `purchase` не надсилається, оскільки реальної покупки немає. Ім’я, телефон і коментар не включаються в параметри подій. У налаштуваннях вебпотоку також перевірте автоматичне вимірювання взаємодій із формами та залиште його вимкненим для цього демонстраційного сценарію.

Код не завантажує Google tag до згоди. Відмову можна змінити посиланням унизу сторінки. Після відкликання попередньої згоди сторінка перезавантажиться, щоб припинити роботу вже завантаженого скрипту.

## Що потрібно для завершення здачі

Поки не виконано зовнішні кроки, роботу не слід описувати як повністю опубліковану чи як таку, що вже збирає статистику. Потрібні:

1. Власний репозиторій і фактичне розгортання GitHub Pages.
2. Власний Measurement ID GA4 і підтверджені події у Realtime або DebugView.
3. Скриншоти сайту, параметрів GitHub Pages і подій GA4 для звіту.

Справжню адресу компанії, контакти й карту не вигадано. Для реального магазину їх потрібно додати після отримання перевірених даних. TERRA та товари — навчальна концепція, не перевірена торгова пропозиція.
